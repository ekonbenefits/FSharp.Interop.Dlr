# Benchmarks

Generated by `Benchmarks/bench.sh docs` (BenchmarkDotNet, short job). Every `dlr { }` is bound and
compiled during warm-up, so a cell is the steady-state cost of one call and what it allocates.
The same operation is done each way it can be: statically, through cached reflection, through
FSharp.Interop.Dynamic (the library this replaces), as C# `dynamic` (the same Microsoft.CSharp
binders, the compiler's own call sites), and in a `dlr { }`.

BenchmarkDotNet v0.15.8, macOS 27.0 (26A428) [Darwin 27.0.0]  
Apple M1 Pro, 1 CPU, 10 logical and 10 physical cores  
.NET SDK 10.0.400

### Beyond C#: what `dynamic` cannot do, or does wrong

C# has no form for an F# function member or an omitted F# optional parameter; a lambda for a `Func` parameter needs a real delegate in C#; `==` on records is reference equality there (the wrong answer).
